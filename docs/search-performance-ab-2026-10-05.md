# 检索性能 A/B 基准

日期：2026-10-05

## 方法

使用 `scripts/benchmark_search_ab.py` 生成同一批本地 fixture 数据，分别执行优化前基线实现和当前实现。测试规模为 200 个文本文件、每个文件 8 个段落，每种操作重复 8 次。指标使用 `time.perf_counter()` 和 `tracemalloc`，报告中位数、P95 和单次调用峰值 Python 内存分配。

基线实现模拟优化前行为：每次调用都重新读取并解析 `library.json`，关键词检索每次都重新读取文本、切分段落和分词。当前实现使用文件状态校验缓存；关键词检索额外缓存段落小写文本和 token 集。

## 结果

| 操作 | 基线中位数 | 当前中位数 | 加速 | 基线峰值 | 当前峰值 |
|---|---:|---:|---:|---:|---:|
| library 加载 | 0.803 ms | 0.295 ms | 2.73x | 0.099 MiB | 0.002 MiB |
| 热缓存关键词检索 | 204.900 ms | 60.133 ms | 3.41x | 0.577 MiB | 0.166 MiB |

P95：library 加载基线 0.870 ms、当前 0.872 ms；关键词检索基线 208.575 ms、当前 61.982 ms。library P95 受微小样本和本地文件系统抖动影响，中位数和内存结果更能反映缓存命中收益。

## 结论

当前缓存优化在重复调用场景下确实有效：library 解析中位延迟下降约 63.4%，关键词检索中位延迟下降约 70.7%，关键词检索 Python 峰值分配下降约 71.2%。该结论适用于 MCP 常驻进程的热缓存场景；首次调用仍需读取和预处理文件，不能按热缓存结果估计冷启动收益。

运行命令：

```powershell
$env:PYTHONPATH='src'
python scripts/benchmark_search_ab.py --files 200 --paragraphs 8 --repeats 8
```
